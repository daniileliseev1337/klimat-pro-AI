# Персонализируемый UI и закрытие существующих UX-недоделок

**Дата:** 2026-07-29
**Статус:** согласовано пользователем, ожидает review спецификации

## Цель

Довести уже существующий интерфейс «КЛИМАТ-ПРО» до законченного состояния и вернуть
сохранённые наработки Claude Design в управляемую модель персонализации. Новые
продуктовые функции не создаются.

## Границы

Включено:

- персональное оформление аккаунта: общий скин и эффект;
- переопределение оформления отдельных панелей на дашборде, в проектах, финансах и задачах;
- каталог 15 скинов и 15 эффектов с ограничением на совместимые пары;
- отдельный режим оформления, запускаемый из профиля;
- исправление существующих UX-недоделок и банка v2.

Не включено:

- MCP-слой, ИИ-модуль, платежи заказчика, общий мессенджер и иные новые продуктовые функции;
- применение миграции к живой БД, production deploy и merge без отдельного явного разрешения владельца.

## Источник визуальных материалов

Рабочий снимок дизайн-системы находится в `design-system/`. Полный неизменяемый
исходный экспорт Claude Design сохранён в
`design-system/_archive/claude-design-export-2026-07-29/`. Архив является источником
для восстановления скинов, эффектов и подтверждения прошлых решений; он не
перезаписывает рабочие файлы автоматически.

## Модель данных

Одна запись предпочтений принадлежит одному пользователю:

```text
user_id
global_skin_id
global_effect_id
panel_overrides: { [panelId]: { skinId, effectId } }
updated_at
```

Каталог оформления является данными приложения: каждый скин и эффект имеет стабильный
ID, подпись, CSS-класс и preview-метаданные. Матрица совместимости определяет, какие
пары видны и могут быть сохранены. Неподдерживаемая пара не применяется и не
сохраняется. При отсутствии предпочтений используется нынешнее спокойное оформление.

RLS разрешает пользователю читать и менять только собственную запись. Настройки
загружаются после авторизации, кешируются локально как best-effort и сохраняются в
аккаунт для синхронизации между устройствами.

## Поведение UI

В `ProfileModal` появляется действие «Настроить интерфейс». Оно включает временный
режим оформления; в обычном рабочем режиме служебных кнопок на панелях нет.

В режиме оформления пользователь:

1. выбирает глобальную пару скин + эффект;
2. открывает любую поддерживаемую панель четырёх основных разделов;
3. оставляет наследование глобальной пары либо выбирает разрешённое переопределение;
4. видит результат сразу;
5. завершает настройку, сбрасывает одну панель или возвращает весь интерфейс к
   общему стилю.

Панели получают стабильные `panelId`; стили применяются через ограниченные CSS-классы
и переменные, а не через произвольный пользовательский CSS. Обязательные текстовые
данные, таблицы, графики и критические действия сохраняют контраст, размер и порядок.
При `prefers-reduced-motion` анимации заменяются спокойным статичным состоянием.

## Доводка существующего функционала

- Банк v2: нормализация мерчанта с префиксом «Оплата товаров и услуг», проверка
  многострочного реального формата, мобильная review-таблица, настройка вариантов
  ФИО владельца для переводов себе и регрессионные тесты.
- UX: действие «Помощь» в `ProfileModal`, корректная подпись self-hosted Supabase,
  мобильная и модальная полировка существующих экранов.

## Последовательность

1. Фундамент оформления: каталог, compatibility matrix, чтение/сохранение предпочтений,
   тесты и миграция в репо.
2. Режим оформления и подключение всех четырёх разделов.
3. Закрытие банка v2 и оставшихся UX-недоделок.
4. Unit-тесты, build, visual QA desktop/mobile, reduced motion, проверка ролей,
   сохранения, сброса и синхронизации.

## Критерии готовности

- Обычный интерфейс остаётся чистым, настройка видна только в отдельном режиме.
- Пользователь может сохранить глобальную пару и переопределить любую поддерживаемую
  панель во всех четырёх разделах.
- Каталог содержит 15 скинов и 15 эффектов, а UI показывает только допустимые пары.
- Выбор пользователя переживает выход/вход и доступен на другом устройстве.
- Банк v2 корректно обрабатывает проверенный формат выписки и остаётся читабельным на
  телефоне.
- Тесты и build проходят; визуальные состояния проверены перед выдачей.
