# Онбординг-тур (Этап 2) — design

> Продолжение онбординг-навигатора. Этап 1 (раздел «Помощь» + команда в Cmd+K) — в проде (merge c2ef665).
> Этап 2 — активная подача «что где» новичку через слайд-тур. Brainstorm + решения владельца: 2026-07-03.

## Цель
Новый пользователь при первом входе получает короткий тур по доступным ему разделам — чтобы сразу
понять, что есть в системе и где это находится. Опытный — может пройти повторно из «Помощи».

## Решения (brainstorm 2026-07-03)
1. **Механика: слайд-тур** (не coachmarks). Карточка по центру экрана, без привязки к живым DOM-элементам —
   надёжно на мобиле и в монолите App.jsx, ноль риска позиционирования.
2. **Запуск: авто при первом входе** любого пользователя + повторный вручную из «Помощи».
3. **Аудитория: все роли**, контент фильтруется по роли (как «Помощь»).

## Архитектура
Ключевой принцип — **переиспользование `helpContent.js` (DRY, §1 бесплатно).** Тур НЕ вводит свой контент
и свою ролевую логику: он идёт по тем же секциям, что отдаёт `helpSectionsFor(TABS.map(t => t.id))` —
уже роль-фильтрованным (§1 подтверждён opus-review Этапа 1: ключи tab = id вкладок TABS). Заказчик видит
слайды только про свои 4 раздела, сотрудник — про все, посетитель — про свои.

### Компонент `src/components/TourModal.jsx`
- Сигнатура: `TourModal({ sections, onClose })`. `sections` — массив (готовый, роль-фильтрованный, форма
  `{ key, title, desc, how }` из helpContent). `onClose()` — вызывается на Готово/Пропустить/клик-фон/Esc.
- Внутренний стейт: `idx` (текущий слайд, 0..sections.length-1).
- Рендер текущей секции: иконка (общая, напр. Compass/HelpCircle — НЕ пер-секционная, YAGNI) + `title` +
  `desc` + `how`. Прогресс: «{idx+1} из {sections.length}» + ряд точек.
- Кнопки: **Назад** (disabled на первом), **Пропустить** (всегда, = onClose), **Далее** (idx<last) /
  **Готово** (idx==last, = onClose). Стрелки ←/→ листают, Esc закрывает.
- Стиль premium-dark, портал в document.body — по образцу HelpModal.jsx (тот же визуальный язык).
- SRP: TourModal только показывает переданные `sections`; фильтрацию и признак «видел» держит App.

### Модификация `src/components/HelpModal.jsx`
- Новый опциональный проп `onStartTour`. Если передан — в шапке модалки (рядом с заголовком) кнопка
  **«Пройти тур»**; клик → `onStartTour()` (App закроет Help и откроет тур). Если проп не передан —
  кнопки нет (обратная совместимость, HelpModal остаётся автономным).

### Модификация `src/App.jsx`
- Стейт `const [tourOpen, setTourOpen] = useState(false);` рядом с `helpOpen`.
- Хелпер завершения: при закрытии тура — `localStorage.setItem("kp-tour-seen", "1")` + `setTourOpen(false)`.
- Авто-старт: `useEffect`, срабатывающий когда `phase === "ready"` — если `shouldAutoStartTour(localStorage.getItem("kp-tour-seen"))` → `setTourOpen(true)`. Триггерится один раз за монтирование ready-состояния (guard от повторного показа при ре-рендерах — по флагу, а не по каждому эффекту).
- Монтирование: `{tourOpen && <TourModal sections={helpSectionsFor(TABS.map(t => t.id))} onClose={handleTourClose} />}`.
- Кнопка «Пройти тур» из HelpModal: передать `onStartTour={() => { setHelpOpen(false); setTourOpen(true); }}`.

### Чистая логика (TDD) — `src/lib/helpContent.js`
- Добавить `export function shouldAutoStartTour(seenFlag)` → `seenFlag !== "1"` (true, если тур ещё не видели).
  Тривиально, но выносим для тестируемости авто-триггера (сам слайд-UI env node не тестирует).
- Тест `src/lib/helpContent.test.js`: `shouldAutoStartTour(null)===true`, `shouldAutoStartTour("1")===false`.

## Data flow
`localStorage("kp-tour-seen")` → `shouldAutoStartTour` → `tourOpen` → `TourModal` получает
`helpSectionsFor(TABS...)` → листание по `idx` → `onClose` пишет флаг «1» → больше не авто-стартует.

## Error handling / edge cases
- `localStorage` недоступен (приватный режим) — обернуть чтение/запись в try/catch (как существующий
  `km_view_mode`/`kp-hc` в App); при ошибке тур просто не помечается «видел» (не критично).
- `sections` пуст (гипотетически) — TourModal при `sections.length===0` сразу вызывает `onClose` (не показывать пустой тур).
- Тур и Help одновременно: открытие тура из Help закрывает Help (setHelpOpen(false)) — не наслаиваются.

## Тестирование
- Unit (vitest, env node): `shouldAutoStartTour` — 2 кейса. Сюита должна остаться зелёной (было 109 → 111).
- Build: `npm run build` зелёная.
- Визуально: первый вход (чистый localStorage) → тур авто-открылся; Пропустить → закрылся, перезаход не показывает;
  «Помощь» → «Пройти тур» → открылся снова; под заказчиком слайдов меньше (только его разделы).

## YAGNI (осознанно НЕ делаем)
- Подсветку живых элементов / привязку к DOM (coachmarks) — отвергнуто в brainstorm.
- Хранение «видел» в профиле/БД — localStorage per-device достаточно.
- Пер-секционные иллюстрации/скриншоты, аналитику прохождения, анимации переходов между слайдами.
